# egfg のまとめ：これまでの実験、分かったこと、論点

- 日付：2026-10-06
- ブランチ：`claude/inspiring-tesla-qrtc2g`
- 各フェーズの詳細は、`docs/superpowers/specs/`（仕様）、`docs/superpowers/plans/`（計画）、`experiments/*_REPORT.md`（レポート）、`results/`（データ）にある。

## 1. 何を作ったか

因子グラフ上の推論の「計算のしかた」を、e-graph（等式飽和）で探して最適化する試作。

- 推論の計算を「因子の積」と「変数についての和（連続なら積分）」の項で表し、分配則・交換律・結合律・和の交換などの規則で、等しい計算を e-graph に集める。
- e-graph から、コスト（演算回数）が最小になる計算を取り出す（抽出：木抽出、貪欲 DAG 抽出、ILP）。
- 取り出した計算は、評価の仕方（半環）を変えるだけで、周辺分布・最頻値・期待値・分散に使い回せる。

## 2. フェーズごとの実験と結果

| フェーズ | 何をしたか | 主な結果 |
|---|---|---|
| 1 | 小さな因子グラフ（変数 3〜8 個）で、BP・ジャンクションツリー（JT）と比較 | 木では BP と同じ計算を再発見し、星形では BP より安い計算（部分積の共有）を見つけた。ループありでも JT 以下。半環の差し替えで最頻値・期待値も正しく求まった |
| A | 探索を軽くするつまみ（規則セット、分割、種まき、抽出法）と規模の曲線（n = 4〜64） | 効いたのは分割だけ。分割なしは n = 8〜12 で壁（e-graph の膨張と ILP の遅さ）。分割ありで n = 64 まで解け、コストは JT の 0.55〜0.85 倍。星形は分割でも壁 |
| B | 時刻ごとに同じ形のモデル（HMM、因子型 HMM、結合 HMM）のフィルタリング。1 時刻分を一度だけ探索して使い回すテンプレート | HMM では前向きアルゴリズムを再発見。鎖が多いモデルでは 0.12〜0.57 倍（鎖を 1 本ずつ予測する）。探索時間は T によらず一定 |
| C | 計算を「観測の前にできる準備」と「観測を待つ部分（待ち時間）」に分け、待ち時間を重く見て抽出 | 「予測を先に済ませ、観測が届いたら更新だけ」の形を自動で選んだ。待ち時間は前向きアルゴリズムの 0.89〜1.00 倍、準備は 1/2〜1/10 |
| D | 線形ガウスモデル。中間結果の表現（モーメント形式・情報形式）を抽出で選ぶ | 状態が 1 本のベクトルでは、カルマンフィルタと情報フィルタの安いほう以下。両者を混ぜた計算（予測はモーメント形式、更新は情報形式）も見つけた。ブロック状態ではカルマンフィルタの 0.28〜0.68 倍 |
| E | 探索の順番（規則の適用の順序と回数） | 種（複数の消去順序の JT）と段階分けの組み合わせで、全ケースで強い比較の相手（best-JT+）以下（0.81 倍）。ただし、その差の大部分は既知の工夫（BP の周辺分布の読み方、部分積の共有）だった |
| F | 消去順序では表せない等式：因子の低ランク分解 | 低ランクの表で大幅に安くなり（r = 1 で 0.007〜0.24 倍）、既知の工夫の最良以下（0.58〜1.00 倍）。因子ごとに「分解するか、しないか」を選んだ |

すべての実験で、出てきた計算の答えは総当たり（または独立な参照の計算）と一致した。

## 3. 分かったこと

1. **e-graph は既知のアルゴリズムを自動で再発見する。** BP、前向きアルゴリズム、カルマンフィルタ、情報フィルタ、予測と更新の分離は、どれも教えずに出てきた。
2. **見つかった改善の大部分は既知の工夫の組み合わせ。** 消去順序、途中結果の共有、部分積の使い回し、周辺分布の読み方。純粋な和と積の規則の範囲では、e-graph の寄与は「既知の工夫を問題ごとに自動で組み合わせる」ことだった（フェーズ E）。
3. **消去順序では表せない等式を足すと、e-graph の強みが出る。** 低ランク分解を因子ごとに使い分ける計算は、「全部分解」「分解なし」のどちらの既知の手法よりも安かった（フェーズ F）。
4. **目的や表現を変えられるのは強み。** 待ち時間（C）や表現の選択（D）は、既存の手法が自動ではしない部分。
5. **規模の壁は探索にある。** e-graph の膨張と ILP の遅さ。対策として、分割（A）、テンプレート（B）、探索の順番（E）が効いた。飽和そのもの（egglog、Rust）は速く、遅いのは ILP。
6. **既定の探索は seeds+staged にした。** 大きな問題でも、強い比較の相手以下が保証される。

## 4. 弱点と、まだ扱っていないこと

- 扱えるのは、離散の表と線形ガウスの厳密な計算だけ。非線形、近似、混合分布（データの対応づけなど）は扱っていない。
- コストは演算回数の目安で、実時間では比べていない。評価器は Python で遅い（コード生成が未実装）。
- 比較の相手が弱かった場面があった（best-JT+ は木では BP より弱い）。
- 既存のライブラリ（GTSAM、pyAgrum）とも比べた（`arena/rounds/libs.md`）。密な離散の問題では、egfg の C が GTSAM（C++）より約 2000〜7000 倍速い。ただし、差の大部分は汎用の実行時エンジンと生成した C との実装の差で、方法の優劣の根拠にはならない。GTSAM の本領の線形ガウスとは、まだ実時間で比べていない。
- ILP は時間切れのとき、改善した解を持たない。
- 低ランク分解のような値に依存する等式は、表が変わると使えるかどうかが変わる。また、e-graph が大きくなって、かえって悪くなる場合があった。
- 線形ガウスで、共分散の計算が観測によらないことを使っていない（平均と共分散をまとめて扱っている）。

## 5. 論点

1. **既存手法に対して、何で勝つと主張するか。**
   - 「専用の手法に自動で追いつく」は今の結果で言えるが、「勝つ」ではない。
   - 一番強い主張は「構造が混ざっていて、既存の手法を 1 つ選んでも最適にならない問題で、全手法の最良（オラクル）に勝つ」こと。フェーズ F の輪や格子がその例。
   - 実時間での比較（同じコード生成、同じ計算機）が必要。
2. **e-graph を使う意味。** 純粋な和と積の範囲では、消去順序の探索で足りる。e-graph の意味は、規則（等式）を外から足していける点にある。足す規則の候補は、表の分解、FFT、行列の恒等式、LLM が提案して検証した規則。
3. **コストの設計。** 新しい等式を足すと、演算ごとのコストが必要になる。方針は、表現と変換として入れる、e-class の性質（ランクなど）を使う、実測で係数を合わせる、正しさとコストを分けて考える。
4. **探索の順番。** 幅優先は大きな問題で破綻する。種と段階分けで改善したが、ノード上限の確認が粗く、上限を大きく超えることがある。
5. **ロボティクスへの応用。** 一般の SLAM などでは既存のライブラリ（GTSAM など）が向いている。向いているのは、構造が固定で高い頻度で回す推定器（テンプレート、待ち時間、表現の選択が効く）。必要なものは、非線形の線形化、多様体、コード生成、データの対応づけ（硬い判断と、パターンごとのテンプレート）。
6. **LLM との関係。** LLM に推定プログラムを書かせる方法は、手軽で範囲が広いが、正しさの保証がない。組み合わせるなら、LLM が計算や規則を提案し、egfg が検証して選ぶ形がよい（和と積の計算は、構造の検査でほぼ完全に検証できる）。
