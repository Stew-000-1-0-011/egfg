# egfg 設計仕様（フェーズ E）：探索の順番

- 日付：2026-10-06
- 状態：レビュー待ち
- 前提：フェーズ D（`2026-10-06-gaussian-design.md`）の実装と実験が完了していること
- 番号について：以前「E」と呼んでいた近似の段階は後回しにしたので、この番号を探索の順番に使う

## 1. 目的

今の飽和は、すべての規則を毎回いっせいに適用する（幅優先）。そのため、ノード上限で打ち切られたとき、e-graph にあるのは「書き換えの回数が少ない式」であって、「良い式」とは限らない。規模の壁（フェーズ A）も、ILP の時間切れ（フェーズ D）も、もとは「e-graph に入る式が多すぎ、しかも有望な順に入っていない」ことにある。

そこで、規則の適用の順番と回数を決める方法（探索の戦略）をいくつか実装し、同じノード数・同じ時間でどれだけ安い計算が得られるかを比べる。あわせて、強い比較の相手（良い消去順序を直接探した計算）と比べ、e-graph が何を足しているのかを測る。

確かめる問い：

- H11（同じ予算での質）：同じノード上限のもとで、順番を工夫した戦略は、幅優先より安い計算を得る。特に、幅優先が壁に当たる規模で差が大きい。
- H12（途中で止めたときの質）：順番を工夫した戦略は、探索の早い段階で良い計算に届く。途中で止めても良い答えが得られる。
- H13（e-graph の寄与）：強い比較の相手より安くなる場合、その差がどの書き換え（消去順序では表せないもの）から来ているかを示す。差がなければ、今の規則の範囲では e-graph の探索は消去順序の探索と同等である、と結論する。

## 2. 戦略

すべて `saturate` の引数 `strategy` で選ぶ。既定は `bfs`（今までと同じ動作）。

### 2.1 bfs（既定）

今までと同じ。すべての規則を 1 回ずつ適用し、ノード上限か繰り返しの上限まで繰り返す。

### 2.2 staged（段階分け）

規則をいくつかの組（ルールセット）に分け、適用の順序と回数を決める。

| 組 | 中身 |
|---|---|
| scope | スコープの解析 |
| push | 分配則の押し込み（Σ_v (a·b) → a·Σ_v b） |
| reorder | 積の交換律・結合律、和の交換 |
| pull | 分配則の逆向き（規則セット `full` のときだけ） |

1 回の「ラウンド」は次の順に行う。

1. scope を飽和させる。
2. push を飽和させる（その間も scope を飽和させ続ける）。
3. reorder を 1 回だけ適用する。
4. pull を 1 回だけ適用する（あるとき）。

ラウンドを、ノード上限か、何も変わらなくなるか、ラウンドの上限まで繰り返す。ねらいは、和を内側へ押し込む有望な書き換えを先に済ませ、組み合わせを爆発させる並べ替え（reorder）の回数を抑えることである。

### 2.3 backoff（当てはまりすぎる規則の一時停止）

egglog のバックオフ方式（`back_off`）を使う。1 回の適用で当てはまる箇所の数が上限（`match_limit`）を超えた規則は、しばらく（`ban_length` 回）適用を休ませ、休むたびに上限を広げる。上限と休む長さは、実験で 2〜3 通り試す。

### 2.4 seeds（複数の消去順序の種）

種まき（S）を広げる。ジャンクションツリー 1 つ（min-fill 順序）ではなく、複数の消去順序から作ったジャンクションツリーを、すべて種として union する。

- 消去順序：min-fill、min-degree、min-weight（消すと生まれる表の大きさが最小の変数から）と、それぞれの同点をランダムに破ったもの（各 4 通り、乱数の種は固定）。
- 種どうしで共有できる途中結果は、e-graph の中で自然にまとまる。

ねらいは、「良い計算の候補」を最初から e-graph に入れ、その近くを書き換えで探すことである。

### 2.5 restart（良い計算から再出発）

1 回の「ラウンド」は次のとおり。

1. 今の e-graph を、少ないノード上限（全体の上限の数分の 1）まで幅優先で広げる。
2. 抽出（木抽出か貪欲 DAG 抽出）で、いちばん安い計算を取り出す。
3. その計算（と種）だけを入れた新しい e-graph を作り直す。

ラウンドを、コストが下がらなくなるか、時間の上限まで繰り返す。ねらいは、e-graph 全体を広げるのではなく、今いちばん安い計算の近くだけを繰り返し探すことである（局所探索に当たる）。

## 3. 強い比較の相手

フェーズ 1〜D の比較の相手（min-fill 順序のジャンクションツリー 1 つ）より強い相手として、次を作る。

- best-JT：2.4 と同じ消去順序の集合（min-fill・min-degree・min-weight と、その同点の破り方）でジャンクションツリーを作り、それぞれのコストを測って最も安いものを選ぶ。
- best-JT+：best-JT の各クリークで、隣から届くメッセージの積を、前と後ろからの部分積で共有する形に作り直したもの。星形で e-graph が見つけた「部分積の使い回し」と同じ種類の、既知の工夫を手で入れたもの。

e-graph の計算が best-JT+ より安くなった場合は、その差の中身を調べる（どの e-class で、どんな形の計算を選んだか）。

## 4. 途中の質の測り方

探索の途中（bfs・backoff では 1 回の適用ごと、staged・restart では 1 ラウンドごと）に、その時点の e-graph から木抽出と貪欲 DAG 抽出をして、次を記録する。

- その時点のノード数、経過時間、抽出したコスト（貪欲 DAG 抽出の値）

これを「ノード数（または時間）に対する、その時点の最安のコスト」の曲線として表に示す。

## 5. 実験

### 5.1 問題

- フェーズ A の種類（鎖、星形、ランダムな木、輪、2 行・3 行の格子、ランダムな疎グラフ）で、分割なしの基準設定が壁に当たる前後の規模（n = 6、8、12、16）。K = 3。
- フェーズ B の結合 HMM の 4 本（1 ステップのテンプレート。e-graph がノード上限に達した例）。
- フェーズ D の結合型の 4 ブロック（同上。表現を考慮した抽出を使う）。

### 5.2 設定

- 戦略：bfs、staged、backoff（2〜3 通り）、seeds、restart、と組み合わせ（seeds ＋ staged、seeds ＋ restart）。
- 規則セット：`full` と `no_reverse`。
- ノード上限：1 万、5 万。時間の上限：1 回 120 秒（フェーズ A と同じ扱い）。
- 最後の抽出：貪欲 DAG 抽出（ILP は時間がかかるので、最後の比較だけに使う）。

### 5.3 記録する値

- 戦略ごと：最終的なコスト、最終的なノード数、探索と抽出の時間、上限到達の有無。
- 途中の質の曲線（4 章）。
- 比較の相手のコスト：min-fill の JT、best-JT、best-JT+、（フェーズ A の）幅優先での結果。
- 正しさ：フェーズ A と同じ（総当たりかジャンクションツリーとの一致）。

### 5.4 成果物

- 結果の CSV（`results/search_order.csv`）と、途中の質の曲線の CSV（`results/search_order_curve.csv`）。
- レポート（`experiments/SEARCH_ORDER_REPORT.md`）：平易な説明つき。表で示す（図は使わない）。H11〜H13 の結果と、e-graph が best-JT+ より安くなった場合の中身。
- 簡易版（`--quick`）を用意し、テストで完走を確かめる。

## 6. テスト

- 既定（bfs）で、これまでのすべてのテストの結果が変わらない。
- どの戦略でも、抽出結果が総当たりと一致する（小さなランダムグラフ）。
- staged：飽和まで回せる小さな問題では、bfs と同じ最安のコストに届く。
- seeds：複数の種を入れても、結果のコストは best-JT 以下になる。
- restart：ラウンドごとのコストが増えない。
- best-JT・best-JT+：総当たりと一致し、best-JT ≤ min-fill の JT、best-JT+ ≤ best-JT。
- 実験スクリプト：簡易版が完走し、CSV に必要な列がそろう。
