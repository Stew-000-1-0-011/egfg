# egfg 設計仕様：e-graph による因子グラフ推論の最適化

- 日付：2026-10-05
- 状態：レビュー待ち
- 目的の位置づけ：学習・探究（研究につながれば発展させる）

## 1. 目的

因子グラフ上の推論（周辺分布、期待値、分散、最頻値）の「計算のしかた」を e-graph（等式飽和）で探索・最適化する試作を作る。
あわせて、次の研究課題を小規模な実験で検証する。

## 2. 研究課題と仮説

**研究課題**：e-graph に一般的な代数規則（分配則など）と「共有部分は 1 回だけ数える」コストだけを与えたとき、全周辺分布を求める最安の計算が、BP（確率伝播法）やジャンクションツリーと同等以上になるか。

- H1（木）：木構造の因子グラフで、DAG 抽出の最小コストは BP のコスト以下になる。さらに、抽出された計算の共有部分は BP のメッセージに対応する。
- H2（ループあり）：ループのあるグラフで、DAG 抽出の最小コストは min-fill 順序によるジャンクションツリーのコスト以下になる（e-graph の規模が許す範囲で）。
- H3（半環の一般性）：同じ抽出結果を (+,×)、(max,×)、期待値半環で評価すると、それぞれ周辺分布、最頻値、期待値・分散が正しく求まる。

各仮説は「総当たりの厳密解との一致」と「演算回数の比較」で検証する。H1 は、実験で確かめたのちに帰納法による証明のスケッチを書く。

## 3. スコープ

対象：
- 離散変数のみ。因子は numpy の確率表（非負の実数テンソル）。
- 規模は小さく、変数 3〜20 程度、状態数 2〜50 程度。
- コストモデルは演算回数（FLOP 数）。空間は「最大中間表の要素数」を副次的な指標として記録するだけにする。

対象外（今後の拡張）：ガウス・連続変数、カルマンフィルタ、近似推論（Loopy BP、MCMC、変分推論）、疎な因子など因子内部の構造の利用、大規模な性能最適化。

## 4. 全体構成

Python パッケージ `egfg` として実装する。各部品は単独でテストできるようにする。

1. **model**：因子グラフを表すデータ構造。変数（名前、状態数）と因子（スコープ、表）を持つ。
2. **ir**：計算を表す項の言語。
   - `Factor(id)`：元の因子
   - `Mul(a, b)`：積（結果のスコープは両者の和集合）
   - `Sum(x, a)`：変数 x についての和（結果のスコープから x を除く）
   - クエリ「p(v) の非正規化周辺分布」は、全因子の積を v 以外の全変数で和をとった項として作る。
3. **egraph**：等式飽和のエンジン。
   - e-class 解析：各 e-class のスコープ（自由変数の集合）。
   - 書き換え規則：積の交換律・結合律、和の交換（Σx Σy = Σy Σx）、分配則（x が a のスコープに無いとき Σx (a·b) = a·Σx b、およびその逆向き）。
   - 爆発対策：ノード数と反復回数の上限。
4. **cost**：コストモデル。Mul のコストは結果スコープの状態数の積、Sum のコストは子のスコープの状態数の積、Factor は 0。
5. **extract**：抽出器を 2 種類用意する。
   - 木抽出（貪欲、ベースライン）：各クエリを独立に選ぶ。
   - DAG 抽出（ILP）：全クエリをまとめて選び、共有ノードのコストを 1 回だけ数える。e-node ごとの 0/1 変数、根の e-class の選択制約、子 e-class の選択制約、循環防止制約で定式化し、PuLP（CBC ソルバ）で解く。
6. **evaluate**：抽出された計算（DAG）を数値で実行する評価器。半環を差し替えられる。sum-product、max-product、期待値半環（期待値と分散）を実装する。
7. **baselines**：比較対象。総当たり（同時分布を全展開）、木上の BP、min-fill 順序の変数消去・ジャンクションツリー、opt_einsum による各周辺分布の個別計算。
8. **experiments**：問題生成器（鎖、ランダムな木、星形、2×n の格子、小さなループ）と、実験スクリプト、結果レポート。

## 5. e-graph エンジンの選択

最初に短い調査（スパイク）を行う。egglog（Python）で次の 2 点ができるかを確かめる。

- スコープを e-class 解析として持ち、それを分配則の適用条件に使えること。
- 飽和後の e-graph 全体（e-class と e-node）を取り出して、自前の ILP 抽出に渡せること。

両方できれば egglog を使い、どちらかが難しければ Python で小さな e-graph を自作する（union-find、ハッシュコンシング、再構築、e-class 解析）。いずれの場合も、他の部品からはエンジンの違いが見えないインターフェースにする。

## 6. 検証方法

- 単体テスト：部品ごとにテストを書く（テスト駆動）。
- 正しさの性質テスト：ランダムな小さい因子グラフで、抽出した計算の評価結果が総当たりと一致すること（周辺分布、最頻値、期待値、分散）。
- 仮説の検証：問題の種類と規模を変えながら、次を記録する。
  - DAG 抽出コストと BP・ジャンクションツリー・opt_einsum のコストの比
  - 抽出結果の共有ノードと BP メッセージの対応
  - e-graph の大きさ、飽和時間、ILP の求解時間
  - 最大中間表の要素数

## 8. 想定されるリスクと対処

- 和の交換規則による e-graph の爆発：ノード数の上限を設け、上限に達したかどうかを結果に記録する。必要なら和の交換をスコープが縮む方向に制限する。
- ILP が遅い：小規模に限定し、時間制限を設けて、最適性が保証されたかどうかを記録する。
- 積の結合律・交換律で、同じ計算が別の形のまま共有されない：結合律・交換律を規則として入れ、そのうえで共有が起きているかを実験で確認する。
