# egfg 設計仕様（フェーズ A）：探索の高速化と規模の曲線

- 日付：2026-10-06
- 状態：レビュー待ち
- 前提：フェーズ 1（`2026-10-05-egfg-design.md`）の実装と実験が完了していること
- 後続：B（時刻の添字を持つテンプレート）、C（インクリメンタルなコスト）は別の仕様で扱う

## 1. 目的

規模を大きくしたときに、探索時間と結果のコストがどう変わるかの曲線を測り、どこで何が壁になるかを調べる。そのために、探索を軽くする 4 つの手段を「切り替えられるつまみ」として実装し、どのつまみがどの壁に効くかを切り分ける。

固定の目標規模は置かない。成果は曲線と、その解釈である。

フェーズ 1 で分かっている壁は 2 つ：
- e-graph が変数 1 個ごとに約 4 倍に増える（変数 8 個の星形でノード上限に到達）。
- ILP 抽出が遅い（e-graph の構築は約 1 秒なのに、ILP は 60 秒の時間制限に到達）。

## 2. つまみ

すべてのつまみについて、「既定値＝フェーズ 1 の動作」とする。既存のテストと実験は変更なしで通ること。

### 2.1 規則セット (R)

`saturate` に規則セットを指定する引数を加える。用意するのは次の 3 種類。

| 名前 | 内容 |
|---|---|
| `full`（既定） | フェーズ 1 と同じ（交換律、結合律の両方向、和の交換、分配則の押し込みと逆向き） |
| `no_reverse` | `full` から逆向きの分配則を除く |
| `minimal` | `no_reverse` から、結合律の一方向 `a*(b*c) → (a*b)*c` を除く |

### 2.2 分割 (D)

予算 `cluster_budget`（クラスタあたりの変数の数の上限、整数または `None`）を指定する。`None`（既定）は分割なし。

1. min-fill 順序でジャンクションツリー（クリーク、クリーク木、因子の割り当て）を作る。フェーズ 1 の部品を流用する。
2. クリーク木の隣接するクリークの組を、併合後の変数の数が小さい順に見ていき、予算以下なら併合する。併合できる組がなくなるまで繰り返す。予算より大きいクリークは単独のクラスタになる。
3. 各クラスタ c について、局所問題を作る。
   - 隣のクラスタ k からのメッセージは「入力」の葉で表す。入力の葉は、名前とスコープ（c と k のセパレータ）だけを持つ。
   - 局所クエリは次の 2 種類で、まとめて 1 つの e-graph に入れる。
     - 隣の各クラスタ j へのメッセージ：c の因子と、j 以外からの入力の積を、c と j のセパレータ以外の変数で和をとったもの。
     - c が受け持つ変数の周辺分布：各変数は、それを含む最初のクラスタが受け持つ。c の因子とすべての入力の積を、その変数以外で和をとったもの。
4. 各クラスタの e-graph から、指定の抽出法で計算を選ぶ。
5. 入力の葉を、そのメッセージを作るクラスタの計算に差し替え、全体を 1 つの `Dag` にする。差し替え後の `Dag` に入力の葉が残らないことを検査する。

### 2.3 種まき (S)

`seed`（真偽値、既定は偽）。真のとき、各クエリの e-class に、既知の計算を表す項を union しておく。どちらも同じ値を表すので、この union は健全である。

- 分割なし：ジャンクションツリー（`junction_tree_dag` と同じ形）の項を種にする。
- 分割あり：各局所クエリに、クラスタ内部を細かいクリークのジャンクションツリーで計算した項を種にする（クラスタの境界は入力の葉）。

これにより、ノード上限で探索が打ち切られても、抽出結果のコストは種の計算以下になる（抽出法が ILP か貪欲 DAG の場合）。

### 2.4 抽出法 (X)

`extractor` に `"greedy"` を加える（既存は `"tree"` と `"ilp"`）。

- 貪欲 DAG 抽出：木抽出の結果から始める。各 e-class について、選んでいるノードを別の候補に替えたときの共有込みの DAG コスト（根から到達できる部分だけ）を計算し、下がるなら替える。どの e-class でも改善がなくなるか、時間制限に達するまで繰り返す。
- 結果は必ず循環を含まず、コストは木抽出以下になる。

## 3. 計算の項への変更

- `ir` に入力の葉を加える（`ENode(op="input", arg=名前, children=())`）。コストは 0。スコープは、クラスタごとの局所問題が持つ対応表から得る。
- egglog 側にも入力の葉の構築子を加え、スコープを設定する。
- 評価器は、入力の葉を含む `Dag` を受け取ったらエラーにする（差し替え漏れの検出）。
- 入力の葉は後続の B で、前の時刻の状態を表すのにも使う。

## 4. 実験

### 4.1 問題

- 種類：鎖、星形、ランダムな木、輪、格子（2 行と 3 行）、ランダムな疎グラフ（ランダムな木に、n/4 本の辺をランダムに足したもの）。
- 規模：変数の数 n ∈ {4, 6, 8, 12, 16, 24, 32, 48, 64}（格子は行数 × 列数が n に最も近いもの）。
- 状態数：K = 3 で固定。
- 乱数の種：ランダムな木とランダムな疎グラフは 0 と 1 の 2 つ。他の種類は 0 のみ。

### 4.2 設定

- 基準：R=`full`、D=`None`、S=偽、X=`ilp`（フェーズ 1 と同じ）。
- 1 つずつ変える：基準から 1 つだけ変える。
  - R ∈ {`no_reverse`, `minimal`}
  - D ∈ {3, 5, 8}
  - S = 真
  - X ∈ {`tree`, `greedy`}
- 組み合わせ（3 つ）：
  - 軽量：R=`minimal`、D=3、S=真、X=`greedy`
  - 中間：R=`no_reverse`、D=5、S=真、X=`greedy`
  - 精密：R=`no_reverse`、D=5、S=真、X=`ilp`

### 4.3 壁の扱い

- 1 回あたりの時間上限は 120 秒（飽和と抽出の合計）。ILP 自体の時間制限は 60 秒のまま。
- ある設定・ある種類で、時間上限に達するか e-graph のノード上限（5 万）に達したら、その設定・種類のそれより大きい n は実行せず、「壁」として記録する。
- 各実行は別プロセスで行い、時間上限を超えたら打ち切る（打ち切りも壁として記録する）。

### 4.4 記録する値

- 時間：飽和、抽出、合計
- e-graph のノード数：全体の合計、クラスタごとの最大
- 上限到達の有無、壁で止まったか
- コスト：結果のコスト、ジャンクションツリーとの比、木なら BP との比、分割なし・基準設定で解けた規模ではそれとの比
- クラスタの数と最大の大きさ

### 4.5 正しさの確認

- n ≤ 12：総当たりの周辺分布と一致すること。
- n > 12：ジャンクションツリーで計算した周辺分布と一致すること。
- 不一致は壁とは別に記録し、レポートで必ず報告する。

### 4.6 成果物

- 結果の CSV（`results/scaling.csv`）。
- レポート（`experiments/SCALING_REPORT.md`）：平易な説明つき。曲線は表で示す（図は使わない）。各つまみがどの壁に効いたか、どこで壁に当たったか、コストの損失はどれくらいかをまとめる。
- 全体の実行時間は 1〜2 時間程度を目安とする。テスト用に、数十秒で終わる簡易版（`--quick`）を用意する。

## 5. テスト

- 各つまみの既定値で、フェーズ 1 のテストがすべて通る。
- 規則セット：どの規則セットでも、抽出結果が総当たりと一致する（小さなランダムグラフ）。
- 分割：予算 3・5・8 で、小さな木・輪・格子の周辺分布が総当たりと一致する。つなぎ合わせ後の `Dag` に入力の葉が残らない。
- 種まき：ノード上限を極端に小さくしても、結果のコストがジャンクションツリー以下になる。
- 貪欲 DAG 抽出：結果に循環がなく、コストが木抽出以下で、値が総当たりと一致する。
- 実験スクリプト：簡易版が完走し、CSV に必要な列がそろう。

## 6. 範囲外

- 割り算などの新しい代数規則、正規分布の因子。
- 規則の完全性や飽和の停止性の証明。
