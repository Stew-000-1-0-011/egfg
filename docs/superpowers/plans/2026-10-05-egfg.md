# egfg Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 離散因子グラフの全周辺分布の計算を egglog の等式飽和で探索し、ILP による DAG 抽出の結果を BP／ジャンクションツリー・総当たりと比較する試作と実験を作る。

**Architecture:** 因子グラフ（model）→ 計算の項（ir）→ egglog で飽和し e-graph を書き出す（egraph）→ 木抽出／ILP DAG 抽出（extract）→ 共通の `Dag` 表現に対してコスト計算（cost）と半環評価（evaluate）。比較対象（baselines）も同じ `Dag` を作るので、同じコストモデルで比べられる。

**Tech Stack:** Python ≥3.10、uv、numpy、egglog 14.x、PuLP（CBC）、opt-einsum、pytest

**Spec:** `docs/superpowers/specs/2026-10-05-egfg-design.md`

## Global Constraints

- Python のプロジェクト管理・依存追加・実行はすべて uv（`uv init`、`uv add`、`uv run`）。pip を直接使わない。
- 依存：`numpy`、`egglog>=14,<15`、`pulp`、`opt-einsum`。開発依存：`pytest`。
- 対象は離散変数のみ。因子は非負の numpy 配列で、軸の順序は因子のスコープの順序に一致する。
- コストモデル（全モジュール共通）：`leaf` = 0、`mul` = 結果スコープの状態数の積、`sum` = 子のスコープの状態数の積。DAG コストは根から到達できる各ノードを 1 回だけ数えた合計。
- 空間の指標は「最大中間表の要素数」（到達可能な各ノードのスコープの状態数の積の最大値）。
- e-graph の上限の既定値：`max_iters=30`、`node_limit=50_000`。ILP の既定の時間制限：60 秒。
- egglog の e-graph 書き出しは非公開 API `EGraph._serialize().to_json()`（egglog 14.0.0 で動作確認済み）を使い、その使用を `egraph.py` の 1 か所に閉じ込める。
- テストは `uv run pytest`。各タスクの終わりにコミットする。

## Review Focus

1. どの因子にも現れない変数：`FactorGraph` の構築時に `ValueError` を出す（Task 1 でテスト）。
2. 表の形がスコープの状態数と合わない、または負の値を含む：`ValueError`（Task 1 でテスト）。
3. 飽和がノード上限で打ち切られた場合：`hit_limit=True` を返し、抽出結果は依然として正しい値を計算する（Task 6・Task 9 でテスト）。
4. 最頻値が同点（一様な表など）：返す割り当ては同時確率が最大値に等しければよい。特定の割り当てを期待しない（Task 9 でテスト）。
5. 変数 1 個・因子 1 個の最小の因子グラフ：全関数が正しく動く（Task 9 でテスト）。

**Files:**
- Create: `src/egfg/evaluate.py`
- Test: `tests/test_evaluate.py`

**Interfaces:**
- Consumes: `Dag`、`dag_scopes`、`node_cost`、総当たり関数（テストのみ）
- Produces:
  - `@dataclass class Table: vars: tuple[str, ...]; data: np.ndarray`（期待値半環では `data` の先頭に成分軸を持つ。下記参照）
  - `class Semiring(Protocol)`：`lift(factor: Factor) -> Table`、`mul(x: Table, y: Table) -> Table`、`sum_out(x: Table, var: str) -> Table`
  - `SUM_PRODUCT`、`MAX_PRODUCT`：sum_out はそれぞれ np.sum、np.max
  - `ExpectationSemiring(feature: dict[int, np.ndarray])`：要素は (p, r, s) の 3 成分（成分軸を先頭に持つ配列）。lift は因子 φ と特徴 h（無い因子は 0）から (φ, φh, φh²)。mul は (p1p2, p1r2 + p2r1, p1s2 + p2s1 + 2r1r2)。sum_out は成分ごとの和。

### Task 6: egglog による等式飽和と書き出し

**Files:**
- Create: `src/egfg/egraph.py`
- Test: `tests/test_egraph.py`

**Interfaces:**
- Consumes: `Term`、`ENode`、`FactorGraph`
- Produces:
  - `@dataclass class EGraphData: classes: dict[str, list[ENode]]; roots: dict[str, str]`（e-class ID → e-node のリスト。`ENode.children` は e-class ID。roots はクエリ名 → e-class ID）
  - `@dataclass class SaturationResult: graph: EGraphData; iterations: int; hit_limit: bool; seconds: float; num_nodes: int`
  - `saturate(fg, queries: dict[str, Term], max_iters: int = 30, node_limit: int = 50_000, reverse_distrib: bool = True) -> SaturationResult`

**egglog 側の定義**（計画作成時の調査で動作確認済みの書き方）：項の型 `T`（`T.factor(i64)`、`T.__mul__`、`T.sum(String, T)`）と、`@function(merge=lambda old, new: old) def scope(t: T) -> Set[String]`。規則は次のとおり。

- スコープの伝搬：因子は fg から設定。積は和集合、和は子のスコープから変数を除く。
- 積の交換律 `a*b → b*a`、結合律 `(a*b)*c ↔ a*(b*c)`。
- 和の交換 `Σx Σy a → Σy Σx a`。
- 分配則（押し込み）：`scope(a)` が x を含まないとき、`Σx (a*b)` と `a * Σx b` を union する。
- 分配則（逆向き、`reverse_distrib=True` のとき）：同じ条件で `a * Σx b` から `Σx (a*b)` を union する。

**飽和の制御**：`run(1)` を 1 反復ずつ実行し、毎回 `all_function_sizes()` の合計を見る。`node_limit` を超えたら `hit_limit=True` で止める。e-graph が変化しなくなったら（サイズが増えなければ）飽和として止める。

**書き出し**：`_serialize().to_json()` を JSON として読み、op が `T` の 3 種の構築子である e-node だけを残す。ルートは、元のクエリの項を下から e-node と照合して e-class を見つける（`_serialize` と op 名の対応関係は、この 1 ファイルの中に閉じ込める）。

### Task 7: 木抽出と ILP DAG 抽出

**Files:**
- Create: `src/egfg/extract.py`
- Test: `tests/test_extract.py`

**Interfaces:**
- Consumes: `EGraphData`、`Dag`、`ENode`、`node_cost`、`dag_cost`、`evaluate`
- Produces:
  - `@dataclass class Extraction: dag: Dag; cost: int; optimal: bool | None; seconds: float`（`dag` のノード ID は e-class ID。`cost` は `dag_cost(dag, fg)`）
  - `class_scopes(g: EGraphData, fg) -> dict[str, frozenset[str]]`
  - `extract_tree(g: EGraphData, fg) -> Extraction`：各 e-class で「自分のコスト＋子の木コストの和」が最小の e-node を、値が変わらなくなるまで繰り返し更新して選ぶ。`optimal=None`。
  - `extract_dag_ilp(g: EGraphData, fg, time_limit_s: float = 60) -> Extraction`

**ILP の定式化**（PuLP、CBC、`msg=False`）：
- 変数：e-node ごとに 0/1 の x_n、e-class ごとに 0/1 の a_c、e-class ごとに連続値 t_c ∈ [0, |C|]（循環防止の順序）。
- 目的：Σ cost_n · x_n の最小化。
- 制約：ルートの e-class は a_c = 1。各 e-class で Σ_{n∈c} x_n = a_c。各 e-node と各子 e-class c' について x_n ≤ a_{c'}。循環防止として、e-node n（e-class c）の各子 c' について t_c ≥ t_{c'} + 1 − (|C| + 1)(1 − x_n)。
- `optimal` は、ソルバの状態が Optimal なら True、時間制限で止まった実行可能解なら False。

### Task 8: ジャンクションツリー（BP）と opt_einsum の比較対象

**Files:**
- Modify: `src/egfg/baselines.py`
- Test: `tests/test_baselines.py`

**Interfaces:**
- Consumes: `FactorGraph`、`Term`、`to_dag`、`Dag`、`dag_cost`、`evaluate`
- Produces:
  - `min_fill_order(fg) -> list[str]`：相互作用グラフで、追加される辺（fill-in）が最小の変数から消去する。同点は名前順。
  - `junction_tree_dag(fg, order: list[str] | None = None) -> tuple[Dag, list[MessageSig]]`：order が None なら min-fill を使う。
  - `MessageSig = tuple[frozenset[int], frozenset[str]]`（メッセージが含む因子 ID の集合と、メッセージのスコープ＝セパレータ）
  - `opt_einsum_cost(fg) -> int`：各変数の周辺分布を `opt_einsum.contract_path(..., optimize="optimal")` で個別に計算した `opt_cost` の合計（参考値。コストモデルが違うため、直接は比べない）。

**ジャンクションツリーの作り方**：
1. 消去順序に従ってクリークを作り、極大でないクリークは除く。
2. セパレータの大きさで最大全域木を作り、クリーク木にする。
3. 各因子を、スコープを含む最小番号のクリークに割り当てる（ψ_i は割り当てられた因子の ID 順の左結合積）。
4. メッセージを項として作る：δ_{i→j} = C_i \ S_ij の変数を名前順に外側から Σ し、中身は ψ_i に k≠j からの δ_{k→i} を k の番号順に掛けたもの。
5. 変数 v の周辺分布は、v を含む最小番号のクリーク i で、C_i \ {v} を同様に Σ したもの（中身は ψ_i とすべての入力メッセージの積）。
6. すべての項を 1 回の `to_dag` に渡して共有させる。

因子を 1 つも割り当てられなかったクリークは ψ を持たない（入力メッセージの積だけ）。木構造の 2 変数因子グラフでは、クリーク＝因子のスコープとなり、この計算は BP（Shafer-Shenoy 型）と同じになる。
