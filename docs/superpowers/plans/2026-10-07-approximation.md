# egfg フェーズ H 実装計画：分布の近似 ― スイッチングモデルでの混合のまとめ

**Goal:** 離散のモードと連続の状態が混ざった時系列モデルのフィルタリングで、混合をまとめる近似の位置を抽出で選び、誤差の上界を実行時に出す。

**Spec:** `docs/superpowers/specs/2026-10-07-approximation-design.md`

## Global Constraints

- 既存の離散・線形ガウスのコードの動作と結果は変えない。既存のテストは変更しない。
- e-graph の飽和は既存の `run_strategy` をそのまま使う（構造だけを渡す。離散と連続の区別は e-graph には見せない）。
- 抽出はフェーズ D の `repextract.extract_rep` をそのまま使う（実装の一覧とコストを渡す）。

## 仕様で決めきれていなかった点の扱い

1. **近似の印**：状態に近似の印は付けない。まとめる演算は「離散の和の e-class の、モーメント形式の状態」を作る実装の 1 つとして入れる（子のスコープに連続の変数があるときだけ）。値が近似かどうかと、その誤差の上界は、実行時に値ごとに持つ（TV の上界 τ。厳密なら 0）。
2. **分ける（factorize）の実現**：GPB1 の形は、メッセージを 2 つ（モードの周辺分布と、連続の状態の周辺分布）に分けた入力とクエリとして作る。連続の側の周辺分布はまとめる演算で求まり、その誤差の上界 Σ_m p(m) KL(N_m ‖ q) は、同時分布と周辺分布の積との KL にちょうど等しい。新しい演算は要らない。
3. **独立な成分**：モデルの因子でつながっていない状態の組（目標ごとのモードと状態など）は、メッセージを成分ごとに分ける。独立なので厳密。成分ごとに「同時（モードごとのガウス）」か「分ける」を選び、すべての組み合わせ（成分 3 個までなら 8 通り）を試す。
4. **近似の罰則**：まとめる演算の抽出のコストに λ ×（まとめる成分の数）を足す。演算回数は別に記録する。λ の値を変えて抽出し、演算回数と近似の量が違う計算の集合を出す。
5. **TV の上界の伝え方**：
   - 和・積分・変換は τ を変えない。まとめるは τ に √(KL の上界 / 2) を足す。
   - 積で、相手が厳密な条件付き分布（新しい子を持つ遷移の因子・遷移の表）なら τ を変えない。
   - それ以外の積（観測の尤度など）は、τ × 2 × sup(相手) × Z(近似の値) / Z(結果) とする（Z は全体の質量）。計算できないとき、両方が近似のときは 1。
6. **答えの取り出し**：モードの確率は離散の周辺分布（厳密な和）。連続の状態の周辺分布はモードについてまとめた 1 つのガウス（出力のための近似。メッセージには入らない）。
7. **参照の実装**：GPB1、GPB2、IMM と、全履歴の数え上げを numpy で直接書く。成分が複数のモデルでは、モードの組を 1 つのモードにし、状態を積み上げたモデルに適用する（状態全体の IMM）。

## File Structure

- `src/egfg/switching.py`：モデル（離散の表、条件付き線形ガウスの因子）、条件付きガウスの値と演算（まとめるを含む）、実装の一覧、テンプレートの探索、フィルタリング、TV の上界。
- `src/egfg/switching_ref.py`：参照の GPB1、GPB2、IMM、数え上げ、モデルの生成器（運動モードの切り替え、目標ごとのモード、外れ値のモード）。
- `experiments/approximation.py`、`experiments/APPROXIMATION_REPORT.md`、`results/approximation.csv`。
- `tests/test_switching.py`。

## Tasks

1. 値と演算（まとめるを含む）とそのテスト。
2. モデル、局所問題（成分・分け方ごとの入力とクエリ）、実装の一覧、抽出、評価。
3. 参照の実装と、一致のテスト（近似のない場合は数え上げと一致、近似のある場合は GPB1・GPB2・IMM との一致）。
4. TV の上界と、1 次元での数値積分との比較のテスト。
5. 実験とレポート。
