- 日付：2026-10-06

- 再現：`uv run python experiments/template.py --out results/template.csv`（3 プロセス並列で約 3 分）。簡易版は `--quick`（約 3 秒）。

## 1. 何を調べたか

隠れマルコフモデル（HMM）のように、同じ形が時刻ごとに繰り返すモデルで、フィルタリング（各時刻で、その時刻までの観測だけを使って状態を推定すること）を行いました。

やり方は次のとおりです。

- 1 時刻分の計算（ステップ）だけを e-graph で探索します。前の時刻から届く情報（前向きのメッセージ）は、入力の葉 `fwd` として受け取ります。
- 変数の名前を時刻の差（`a@-1`、`a@0`）で書くので、時刻 1 以降のステップはすべて同じ問題になります。探索は「先頭（時刻 0）」と「途中（時刻 1 以降）」の 2 回だけです。
- 見つかった計算（テンプレート）を、時刻 0 から順に当てはめて評価します。

確かめた問いは 2 つです。

- H4：1 ステップの計算のコストは、前向きアルゴリズム以下になるか。
- H5：探索の時間は T によらず一定で、全体のコストは T に比例するか。

### 比べたもの

| 名前 | 中身 |
|---|---|
| forward | 前向きアルゴリズム（教科書どおり）。前向きのメッセージと遷移の因子をすべて掛け、前の時刻の変数で和をとってから（予測）、観測の因子を掛ける（更新） |
| jt | 1 ステップの局所問題のジャンクションツリー。探索はしない（種まきの種と同じもの） |
| default | e-graph の探索。規則はすべて、種まきあり、ILP 抽出 |
| light | e-graph の探索。規則は最小限、種まきあり、貪欲 DAG 抽出 |

### モデル

状態数はすべて K = 3 です。

| 名前 | 中身 |
|---|---|
| hmm | 状態変数 1 個の HMM |
| fhmm2〜4 | 因子型 HMM。m 本（2〜4 本）の独立な鎖が、1 つの観測の因子でつながる |
| chmm2〜4 | 結合 HMM。鎖 i の次の状態は、前の時刻の鎖 i と鎖 i−1 で決まる。観測は鎖ごとに 1 つ |

T は 1、2、4、8、16、64、256、1024 です。

## 2. 結論の要約

1. **H4：「はい」。** すべてのモデルで、e-graph が選んだ 1 ステップの計算のコストは、前向きアルゴリズム以下でした。
   - HMM では前向きアルゴリズムと同じ計算になりました（前向きアルゴリズムを再発見しました）。
   - 鎖が 2 本以上あるモデルでは、前向きアルゴリズムより安くなりました。前向きアルゴリズムの 0.12〜0.57 倍、ジャンクションツリーの 0.43〜0.84 倍です。鎖が多いほど差が大きく、因子型 HMM の 4 本では約 9 分の 1 でした。
2. **H5：「はい」。** 探索はモデルと設定ごとに 1 回だけで、時間は T によりません（T = 1 でも T = 1024 でも同じ）。全体のコストは「先頭 ＋（T−1）× 途中」で、T に比例します。T = 1024 でも評価は 0.6 秒以内で終わりました。
3. **安くなった理由**：予測のところで、鎖を 1 本ずつ処理していました。前向きアルゴリズムは前の時刻と今の時刻の状態を全部まとめた表（m 本なら K の 2m 乗の大きさ）を作りますが、e-graph は「1 本の鎖の遷移を掛けて、その鎖の前の時刻の変数で和をとる」を鎖ごとに繰り返し、表の大きさを K の m+1 乗に抑えていました（5 章）。
4. **探索の時間**：light はどのモデルでも 2.2 秒以内でした。default は、ILP 抽出が遅いため、因子型 HMM の 4 本と結合 HMM の 3〜4 本で 32〜155 秒かかりました。結合 HMM の 4 本では、default も light も e-graph のノード上限（5 万）に達し、default は時間上限（120 秒）も超えました。それでも種まきのおかげで、コストはジャンクションツリーより安いままでした。
5. **正しさ**：224 行すべてで、確認したすべての時刻の答えが参照の値と一致しました（最大誤差 1e-14 程度）。T = 1024 でも値が小さくなりすぎる（アンダーフロー）ことはありませんでした。

## 5. e-graph が見つけた計算

因子型 HMM の 2 本（fhmm2）の途中のステップです。`T0`、`T1` は鎖 0・1 の遷移の因子、`O` は観測の因子、`fwd` は前の時刻からのメッセージ（前の時刻の 2 本の鎖の同時分布）です。

前向きアルゴリズム（コスト 243）：

```
v0 = fwd * T0          （x0@-1, x1@-1, x0@0 の表：27）
v1 = v0 * T1           （x0@-1, x1@-1, x0@0, x1@0 の表：81）
v2 = Σ_x1@-1 v1        （81）
v3 = Σ_x0@-1 v2        （27）
v4 = v3 * O            （9）  → 次の時刻へのメッセージ
x0 の周辺分布 = Σ_x1@0 v4（9）、x1 の周辺分布 = Σ_x0@0 v4（9）
```

e-graph（コスト 135）：

```
v0 = T1 * fwd          （x0@-1, x1@-1, x1@0 の表：27）
v1 = Σ_x1@-1 v0        （27）  ← 鎖 1 の前の時刻の変数を、すぐに消す
v2 = T0 * v1           （x0@-1, x0@0, x1@0 の表：27）
v3 = Σ_x0@-1 v2        （27）  ← 鎖 0 の前の時刻の変数を消す
v4 = O * v3            （9）  → 次の時刻へのメッセージ
x0 の周辺分布、x1 の周辺分布は前向きアルゴリズムと同じ（9 ずつ）
```

違いは、前向きアルゴリズムが 4 変数の表（81 要素）を作るのに対し、e-graph は鎖を 1 本ずつ処理して 3 変数の表（27 要素）までに抑えている点です。これは、変数消去の順序を工夫して「予測」を鎖ごとに分けて行うことに当たります。鎖が m 本なら、前向きアルゴリズムの表は K の 2m 乗、e-graph の表は K の m+1 乗の大きさになり、鎖が多いほど差が開きます。

結合 HMM の 2 本（chmm2）でも同じ形が見つかりました。さらに、鎖 1 の観測の因子 `O[x1@0]` を、鎖 0 の遷移を掛ける前の小さな表（9 要素）に掛けていました。

これらの工夫は、分配則と結合律・交換律だけから見つかったもので、e-graph にはフィルタリングのアルゴリズムを何も教えていません。

## 6. 正しさの確認

各 T について、最初の 8 時刻、最後の時刻、その間の 8 時刻程度でフィルタリングの答えを確かめました。比べた相手は、時刻 t までで展開した因子グラフの時刻 t の周辺分布で、求め方は大きさで分けています。

- 変数が 12 個以下：総当たり
- 64 個以下：ジャンクションツリー（時刻順の消去順序）
- それより大きい：状態をまとめた行列で直接計算する参照計算（numpy だけで書いた、egfg の評価器とは独立のもの）

224 行すべてで一致しました。最大誤差は 1e-14 程度です。

このほか、テスト（`tests/test_dynamic.py`）で次のことを確かめています。

- 1 ステップずつ進める評価（`Filter.step`）の結果が、一度に評価した結果と一致する。
- 最頻値（max 周辺）と期待値・分散が総当たりと一致する。
- 全時刻分を 1 つの計算に展開すると、そのコストが「先頭 ＋（T−1）× 途中」と一致する。

## 7. 注意点

- **割り算はコストに含めていない**：アンダーフローを防ぐため、前向きのメッセージを毎回、和が 1 になるように割っています。この割り算（1 ステップあたり、メッセージの要素数ぶん）は、フェーズ 1・A のコストモデルとそろえるためコストに含めていません。比べた相手もすべて同じ扱いです。
- **大きな T の正しさの確認**：仕様ではジャンクションツリーと比べる予定でしたが、展開した因子グラフの変数が 64 個を超えると今の実装では遅すぎるため、上の参照計算で確かめました。参照計算自体は、小さな T で総当たりと一致することをテストで確かめています。
- **chmm4 の探索**：default は探索に 155 秒かかり、時間上限（120 秒）を超えました。e-graph もノード上限に達しています。結果は正しく、コストもジャンクションツリー以下ですが、探索が最後まで終わっていないので、もっと安い計算がある可能性があります。
- **ステップの中の分割**：今回は実装していません。鎖がさらに多いモデルでは、フェーズ A の分割をステップの中に使う必要があります。

## 8. 次の課題

1. **C（インクリメンタルなコスト）**：今は 1 ステップのコストを記録しただけです。新しい観測が届いたときの追加の計算を目的にして探索し、オンラインの推定に向けて最適化します。今回見つかった計算は、そのまま出発点になります。
2. **ステップの中の分割**：鎖が 5 本以上のモデルで、ノード上限の壁を越えるため。
3. **抽出の高速化**：探索時間のほとんどが ILP でした。フェーズ A と同じ課題です。
