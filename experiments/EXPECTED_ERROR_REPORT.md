# 実験レポート（フェーズ I）：観測についての仮定による、近似の誤差の期待値の事前計算

- 日付：2026-10-07
- データ：`results/expected_error.csv`、ログ：`results/expected_error.log`
- 再現：`uv run python experiments/expected_error.py --out results/expected_error.csv`（約 50 分。ほとんどが 3 つの目標のモデル）
- 仕様：`docs/superpowers/specs/2026-10-07-expected-error-design.md`、計画：`docs/superpowers/plans/2026-10-07-expected-error.md`

## 1. 何を調べたか

フェーズ H では、混合をまとめる位置を粗い罰則 λ で選んだ。ここでは「観測はモデルから生まれる」と仮定し、まとめる演算 1 回あたりの期待 KL の上界 ε を、モデルのパラメータだけから計算した（シミュレーションなし）。

- ε の求め方：まとめの誤差の恒等式 ½ log det（まとめた共分散）− ½ 平均 log det（成分の共分散）の期待値を、第 1 項は窓の観測による線形推定の誤差で上から、第 2 項は全てのモードの列を知ったときのカルマン共分散の平均で下から押さえた。必要なのは 1 次・2 次のモーメントだけ。
- 抽出：まとめる実装のコストに μ × ε を足す（μ：誤差 1 nat あたり何回の演算に相当するか）。答えを出すためだけのまとめ（全てのモードについての状態の周辺分布）は、どの計算にも必要でメッセージを変えないので数えない。
- 比較：μ を 9 通り（0〜10⁴）、フェーズ H の λ を 5 通り（0〜10⁶）変え、それぞれで全てのメッセージの形の中から一番安い計算を選んだ。
- 測ったもの：各計算の ε の合計（1 ステップあたり、事前）、実行時のまとめの KL の上界の平均（モデルから生成した観測で測った値。比較のためだけ）、実際の誤差（全てのモードの履歴を数え上げた厳密な事後分布との差。長い実行では GPB2 との差）。

## 2. 結論の要約

1. **H20（選択の質）：「はい」。** μ を上げると、選ばれる計算が GPB1 → IMM → GPB2 と、演算回数が増えて誤差が減る順に並んだ。λ では、メッセージの形をまたいで選ぶと、どの λ でも GPB1（またはそれより悪い計算）しか選ばれなかった。λ は「まとめる回数」を数えるので、まとめる回数が一番少ない GPB1 が常に有利になる。
2. **3 つの目標のモデルでは、μ ≥ 300 で目標ごとの GPB2 が選ばれた。** 演算回数 102（状態全体の GPB2 は 9000）、誤差は状態全体の GPB2 と同じ。フェーズ H で λ = 0 のときに出た「安いが誤差の大きい置き方」は選ばれなかった。λ では、メッセージの形をまたぐとこの計算に届かなかった。
3. **H19（上界）：事前の値は、実測の平均を全ての計算で上回った。** ただし 3〜80 倍と緩い。順位は、同じメッセージの形の中でも、形をまたいでも、実際の誤差の順と合った（GPB2 < IMM < GPB1）。
4. **限界：時間をまたいだ蓄積を見ていない。** モードの TV で、GPB1 の実際の誤差は IMM の 8〜12 倍、GPB2 の 8〜74 倍なのに、ε の比は 1.5〜2.7 倍しかない。GPB1 はモードと状態の関係を毎ステップ捨て、それが後のモードの推定に響くが、ε は 1 ステップの局所の誤差しか見ないため。そのため、GPB1 から離れるには大きな μ（100〜300）が要り、IMM は狭い μ の範囲でしか選ばれなかった。
5. **ε の計算は速い。** モデルごとに 0.01〜0.15 秒（まとめる位置の形 3〜6302 通り）。時間の大半は e-graph の抽出（3 つの目標で 1 回 60 秒前後）。

## 3. μ による選択（1 つの成分のモデル）

演算回数は 1 ステップあたり。ε は 1 ステップあたりのメッセージに関わるまとめの ε の合計、実測は実行時のまとめの KL の上界の平均。

|---|---|---|---|---|---|---|---|
| maneuver(2,1) | 0〜30 | GPB1 | 18 | 0.32 | 0.073 | 0.095 | 0.17 |
| | 100 | IMM | 26 | 0.21 | 0.032 | 0.012 | 0.057 |
| | 300〜 | GPB2 | 32 | 0.18 | 0.020 | 0.0014 | 0.0038 |
| maneuver(3,1) | 0〜100 | GPB1 | 30 | 0.27 | 0.084 | 0.18 | 0.22 |
| | 300 | IMM | 51 | 0.14 | 0.020 | 0.016 | 0.062 |
| | 1000〜 | GPB2 | 69 | 0.12 | 0.015 | 0.0025 | 0.0066 |
| maneuver(2,2) | 0〜100 | GPB1 | 62 | 0.72 | 0.21 | 0.22 | 0.31 |
| | 300〜 | GPB2 | 128 | 0.33 | 0.091 | 0.026 | 0.055 |
| maneuver(3,2,obs) | 0〜100 | GPB1 | 96 | 1.47 | 0.30 | 0.44 | 0.84 |
| | 300〜 | GPB2 | 279 | 0.55 | 0.079 | 0.0097 | 0.057 |

- λ では、どのモデルでも、どの λ でも GPB1 が選ばれた（外れ値のモデルは候補が 1 つだけ）。
- IMM の演算回数が、フェーズ H の 22・39 より多い（26・51）。μ を掛けると、同じ IMM の数値を出す計算のうち、ε の小さい置き方（答えのためのまとめを共有しない形）が選ばれたため。
- 外れ値のモデルでは ε が実測の 30〜80 倍と、特に緩かった。外れ値の観測の雑音（100 倍）が大きく、線形推定の誤差（第 1 項）が真の誤差を大きく上回るため。

| モデル | 選ばれる μ | 計算 | 演算回数 | ε | 実測 | モードの TV | 平均の誤差 |
|---|---|---|---|---|---|---|---|
| targets(2,2,1) | 0〜1 | 目標ごとの IMM | 44 | 1.35 | 0.34 | 0.020 | 0.080 |
| | 3〜10 | 目標ごとの IMM | 48 | 0.65 | 0.11 | 0.020 | 0.080 |
| | 30 | 目標ごとの GPB1 | 60 | 0.70 | 0.14 | 0.15 | 0.36 |
| | 100〜 | 目標ごとの GPB2 | 76 | 0.42 | 0.038 | 0.0060 | 0.023 |
| targets(2,2,2) | 0〜30 | 分けたメッセージ（GPB1 に近い） | 150 | 1.88 | 0.41 | 0.27 | 0.29 |
| | 100〜 | 目標ごとの GPB2 | 264〜268 | 0.77 | 0.17 | 0.042 | 0.090 |
| targets(3,2,1) | 0〜100 | 目標ごとの GPB1 | 54〜60 | 1.41 | 0.20 | 0.093 | 0.18 |

- 状態全体の GPB2 は、それぞれ 760、3344、9000 回。目標ごとの GPB2 は 1/10、1/13、1/88 で、誤差は同じ。
- targets(2,2,1) の μ = 30 では、GPB1（60 回、ε 0.70）が選ばれた。IMM（48 回、ε 0.65）のほうが演算回数でも ε でも小さいので、選択がおかしい。貪欲な抽出が局所解で止まったためと考えられる（メッセージの形の中での抽出が、μ によって違う局所解に入る）。
- 同じ IMM の数値を出す計算でも、ε が 1.35 と 0.65 と違うことがあった。他の目標の変数も含む値でまとめると、数値は同じでも上界の計算が緩くなるため。

## 5. 上界と実測（H19）

- 全 28 の計算で、ε（事前）は実測の平均以上だった。比は 3〜82 倍（中央値 7 倍）。
- 仕様のとおり、ε は「まとめる前の値が厳密なとき」の上界。実測は近似の入った値で測っているので、厳密な比較ではない。厳密な入力での比較は、1 次元の先頭の時刻で、観測についての数値積分で行い、上界が成り立つことを確かめた（テスト）。

## 6. 実装中に見つかった問題

- **答えのためのまとめを罰則に数えていた。** どの計算も、状態の周辺分布を答えるために全てのモードについてまとめる。分けたメッセージ（GPB1）ではそれがメッセージと同じまとめなので 1 回、同時のメッセージ（IMM・GPB2）では別に 1 回となり、GPB1 が不当に有利になっていた。メッセージに関わらないまとめは罰則から外した。
- **定常の 2 次モーメントが存在しないモデル。** 位置と速度のモデルは位置が積分されて発散するので、定常状態がない。時刻 50 のモーメントを使うようにした（安定なモデルでは定常状態と同じ）。
- **抽出の木の計算に時間の上限がなかった。** 3 つの目標では 1 回の抽出に 1 分近くかかった。終わる保証はあるが長くなりうるので、抽出の制限時間を過ぎたらその時点の結果を使うようにした。

## 7. 分かったこと

1. シミュレーションに頼らない誤差の期待値の上界は、モデルのパラメータだけから速く計算でき、実測を上回り、順位も正しかった。これを抽出の価格に使うと、λ ではできなかった「メッセージの形をまたいだ、演算回数と誤差のつりあいの選択」ができた。
2. 1 ステップの局所の誤差しか見ないので、誤差の蓄積の大きい手法（GPB1）を過小評価する。時間をまたいだ蓄積（モードの連鎖の混ざる速さによる縮み）の評価が次の課題。
3. 上界は 3〜82 倍緩い。とくに観測の雑音が大きいモードがあるとき。抽出の選択には順位が合っていれば足りるが、精度の保証として使うには緩い。
4. 貪欲な抽出の局所解のため、μ を上げても選択が単調にならない場合があった。
