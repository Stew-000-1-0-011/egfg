# 実験レポート（フェーズ E）：探索の順番

- 日付：2026-10-06
- データ：`results/search_order.csv`（全 936 行）、途中の質の曲線：`results/search_order_curve.csv`、ログ：`results/search_order.log`
- 再現：`uv run python experiments/search_order.py --out results/search_order.csv`（3 プロセス並列で約 35 分）。簡易版は `--quick`（約 3 秒）。
- 仕様：`docs/superpowers/specs/2026-10-06-search-order-design.md`、計画：`docs/superpowers/plans/2026-10-06-search-order.md`

## 1. 何を調べたか

これまでの飽和は、すべての規則を毎回いっせいに適用していました（幅優先、bfs）。これを、規則の適用の順番と回数を変える次の戦略と比べました。

| 戦略 | 中身 |
|---|---|
| bfs | 今までどおり。すべての規則をいっせいに適用する |
| staged | 1 ラウンドに、和の押し込み（分配則）を 3 回、並べ替え（交換律・結合律・和の交換）を 1 回、分配則の逆向きを 1 回だけ適用する |
| backoff | egglog のバックオフ。当てはまりすぎる規則をしばらく休ませる（標準：上限 1000・休み 5、きつめ：上限 200・休み 2） |
| seeds | 複数の消去順序（min-fill・min-degree・min-weight と、それぞれ同点のランダムな破り方 4 通り）のジャンクションツリーを、すべて種として入れる |
| restart | 小さく広げて最安の計算を取り出し、その計算から e-graph を作り直す、を繰り返す |
| seeds+staged、seeds+restart | 組み合わせ |

比べる相手には、これまでより強い best-JT+ を作りました。複数の消去順序のジャンクションツリーのうち最も安いもの（best-JT）に、クリークでのメッセージの積を前と後ろからの部分積で共有する工夫を加えたものです。

問題は、フェーズ A の 7 種類（n = 6〜16、K = 3、28 ケース）、フェーズ B の結合 HMM の 4 本（1 ステップ）、フェーズ D の結合型の正規分布 4 ブロック（1 ステップ）です。規則は full と no_reverse、ノード上限は 1 万と 5 万で試しました。最後の抽出は貪欲 DAG 抽出です。

## 2. 結論の要約

1. **H11（同じ予算での質）：「はい」。ただし種なしでは大きな問題に届かない。**
   - 種を使わない戦略どうしでは、staged・backoff・restart が bfs より大きく良くなりました。n ≥ 12 の幾何平均（best-JT+ との比）は、ノード上限 5 万で bfs 2464 倍に対し、staged 168 倍、backoff 496 倍、restart 9.2 倍です。
   - それでも、種がなければ n ≥ 12 では best-JT+ よりはるかに悪いままでした。e-graph が良い形にたどり着く前に、ノード上限に達してしまいます。
   - 種を使うと、すべてのケースで best-JT+ 以下になりました。中でも seeds+staged は、28 ケースすべてで best-JT+ より安くなりました（幾何平均 0.81 倍）。
2. **H12（途中で止めたときの質）：「はい」（種ありの場合）。** seeds+staged は、数千ノード・数秒の時点で、ほぼ最終的なコストに届いていました（5 章）。種なしの戦略は、最後まで改善が続き、良い計算には届きませんでした。
3. **H13（e-graph の寄与）：大部分は既知の工夫だった。**
   - 木（鎖・ランダムな木）では、seeds+staged のコストは、因子グラフ上の BP とちょうど同じでした。best-JT+ との差は、「周辺分布をクリークからではなく、変数に届くメッセージの積から読む」という、BP がもともとしている既知の工夫そのものでした。今回の best-JT+ には、これが入っていませんでした。
   - BP より安くなったのは、星形だけでした（BP の 0.88〜0.98 倍）。部分積の共有によるもので、これもフェーズ 1 で見つかった工夫と同じ種類です。
   - ループのあるグラフ（輪・格子・疎グラフ）では、best-JT+ の 0.73〜0.98 倍でした（規則 full、上限 5 万）。同じ種類の工夫（周辺分布を小さな表から読む）によると考えられますが、中身はまだ確かめていません。
   - 結論として、今の規則の範囲での e-graph の寄与は、「既知の工夫を問題ごとに自動で組み合わせる」ことでした。既知の手法を超える新しい計算は見つかっていません。
4. **テンプレート**：B の結合 HMM の 4 本では backoff が最良でした（2493。bfs は 2592〜2907、1 ステップのジャンクションツリーは 3177）。D の正規分布の 4 ブロックでは、backoff（きつめ）が 1008 になりました（D の最良は 1736、カルマンフィルタは 2560）。
5. **正しさ**：936 行すべてで、答えが参照の値と一致しました。

## 3. 戦略ごとのまとめ（フェーズ A の 28 ケース、規則 full）

値は best-JT+ のコストに対する比（小さいほどよい）の幾何平均です。「1 未満」は、best-JT+ より安くなったケースの数です。

| 戦略 | n ≤ 9（上限 1 万） | n ≥ 12（上限 1 万） | n ≤ 9（上限 5 万） | n ≥ 12（上限 5 万） | 1 未満（上限 5 万） | 探索の時間の最大（上限 5 万） |
|---|---|---|---|---|---|---|
| bfs | 2.19 | 4801 | 1.33 | 2464 | 7 / 28 | 26.3 秒 |
| staged | 1.42 | 621 | 1.01 | 168 | 9 / 28 | 2.7 秒 |
| backoff | 1.41 | 1150 | 1.22 | 496 | 5 / 28 | 2.5 秒 |
| backoff（きつめ） | 1.73 | 968 | 1.73 | 911 | 4 / 28 | 0.9 秒 |
| restart | 1.43 | 142 | 1.00 | 9.19 | 7 / 28 | 38.7 秒 |
| seeds | 0.85 | 0.93 | 0.84 | 0.91 | 24 / 28 | 22.5 秒 |
| seeds+staged | **0.81** | **0.84** | **0.82** | **0.81** | **28 / 28** | 5.7 秒 |
| seeds+restart | 0.88 | 0.96 | 0.84 | 0.93 | 24 / 28 | 7.6 秒 |

- 規則 no_reverse でも、ほぼ同じ傾向でした（seeds+staged は n ≥ 12、上限 5 万で 0.81 倍、28 / 28）。
- seeds だけでも best-JT+ 以下は保証されます（種そのものを選べるため）。そこに staged を組み合わせると、種の近くの書き換えで、さらに 1〜2 割安くなりました。
- restart は種なしの中では最良でしたが、時間がかかりました（最大 39 秒）。

## 5. 途中の質（規則 full、ノード上限 5 万）

各段階での「その時点のノード数：抽出したコスト」です。

| ケース | 戦略 | 途中の経過 |
|---|---|---|
| 星形 16 | bfs | 164：2.3 億 → 4,761：7,534 万 → 37,921：3,337 万 → 763,380：1,387 万 |
| 星形 16 | staged | 164：2.3 億 → 11,570：325 万 → 52,345：48 万 |
| 星形 16 | restart | 37,921：3,337 万 → 54,301：16 万 → 53,062：4,857 → 61,468：3,516 |
| 星形 16 | seeds | 923：1,467 → 10,453：843 → 72,052：813 |
| 星形 16 | seeds+staged | 923：1,467 → 3,794：1,011 → 28,505：855 → 168,715：747 |
| 2 行の格子 16 | seeds+staged | 1,027：2,412 → 18,202：1,962 → 88,319：1,935 |
| 輪 16 | seeds | 578：2,088 → …（ずっと 2,088） |
| 輪 16 | seeds+staged | 578：2,088 → 9,330：1,926 |

- 種なしの戦略は、元のクエリ（全部掛けてから和をとる、非常に高い計算）から出発し、少しずつ下がっていきます。上限までに良い計算には届きません。
- 種ありの戦略は、最初から best-JT+ 程度のコストで始まり、数千〜数万ノードでほぼ最終的な値になります。
- seeds（幅優先）は、種の近くを広げても改善しないことが多くありました（輪 16 は最後まで 2,088）。staged と組み合わせると改善しました。和の押し込みを先に済ませると、種の近くの「より安い読み方」に早く届くためと考えられます。

## 6. 注意点

- **ノード上限を超えることがある**：上限の確認は、1 回の適用（bfs）や 1 段階（staged）の後にしかしていません。そのため、1 回で上限を大きく超えることがあります。bfs は最大 138 万ノード（上限 5 万）、staged と backoff は最大 12〜15 万ノードでした。「同じ予算での比較」は、この意味で近似です。表の比較は、実際に使ったノード数（CSV の nodes）と合わせて読む必要があります。
- **best-JT+ は十分に強い相手ではなかった**：木では BP より弱いことが分かりました。次に e-graph の寄与を測るときは、少なくとも「因子グラフ上の BP（木の場合）」と「周辺分布を最小の表から読むジャンクションツリー」を比較の相手に加える必要があります。
- **ループのあるグラフでの差の中身は未確認**：0.73〜0.98 倍の差が何から来ているかは、まだ計算の中身を見て確かめていません。
- **テンプレートでの戦略の差は小さい**：テンプレートは最初から種（1 ステップのジャンクションツリー）を持っているので、戦略による差は 1〜2 割でした。

## 7. 次の課題

1. 比較の相手をさらに強くする（BP、周辺分布を最小の表から読むジャンクションツリー）。そのうえで e-graph の寄与を測り直す。
2. 既定の探索を seeds+staged にする（今は bfs）。大きな問題では、これだけで結果が大きく良くなる。
3. ノード上限の確認を細かくする（1 回の適用の中で上限を超えないようにする）。
4. 今の規則の範囲では、e-graph の寄与は既知の工夫の組み合わせだった。新しい計算を見つけるには、消去順序では表せない規則（表の分解、FFT など）を足す必要がある（前の議論のとおり）。
