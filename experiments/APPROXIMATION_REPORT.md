# 実験レポート（フェーズ H）：分布の近似 ― スイッチングモデルでの混合のまとめ

- 日付：2026-10-07
- データ：`results/approximation.csv`、ログ：`results/approximation.log`
- 再現：`uv run python experiments/approximation.py --out results/approximation.csv`（約 6 分）。簡易版は `--quick`。
- 仕様：`docs/superpowers/specs/2026-10-07-approximation-design.md`、計画：`docs/superpowers/plans/2026-10-07-approximation.md`

## 1. 何を調べたか

離散のモード（マルコフ連鎖）によって、連続の状態の動きや観測のされ方が切り替わるモデル（スイッチングモデル）のフィルタリングを扱った。厳密に計算すると、状態の事後分布はモードの履歴ごとのガウスの混合になり、成分の数が時刻とともに指数的に増える。そこで、混合を 1 つのガウスにまとめる演算（平均と共分散を一致させる射影）を入れ、どこでまとめるかを抽出に選ばせた。

- e-graph の等式は厳密なまま（構造だけを飽和させる）。まとめる演算は、「連続の変数が残っている値の、離散の変数についての和」を計算する唯一の実装として、抽出の候補に入る。
- メッセージ（次の時刻に渡す値）の形は 2 通り試す。
  - 同時：モードごとのガウス。
  - 分ける：モードの分布と、1 つのガウスの積。
  - 互いに独立な成分（目標ごとのモードと状態）は、常に成分ごとに分ける。これは厳密。
- 抽出のコスト：演算回数 ＋ λ ×（まとめる成分の数）×（1 ＋ まだ掛けていないその時刻の観測の数）。後ろの因子は、観測の前に作った誤差は観測で増幅されうる（6 章の上界の伝え方と同じ構造）ことを反映する。λ = 0 と λ = 10⁶ を試した。
- 参照：GPB1、GPB2、IMM を numpy で直接書いたもの。状態全体（モードの組を 1 つのモード、状態を積み上げたもの）に適用したもの（state-wide）は、同じ探索を積み上げたモデルにかけて、同じコストモデルで数えた。
- 誤差：観測をモデルから生成し（種 3 つ）、全てのモードの履歴を数え上げた厳密な事後分布と比べた（T = 8、モードの組が多いモデルは T = 5）。長い実行（T = 50）では GPB2 との差を測った。

### モデル

| 名前 | 中身 |
|---|---|
| maneuver(M, d) | モード M 通り（静か・機動・減速）。d = 1 はスカラーの状態、d = 2 は位置と速度。`obs` は観測の雑音もモードで変わる |
| outlier(d) | 状態は 1 つの線形ガウス。各時刻の観測が確率 0.1 で外れ値（雑音 100 倍）。外れ値の印は時刻ごとに独立 |
| targets(k, M, d) | k 個の独立な目標。それぞれが自分のモードと状態を持ち、目標ごとに観測される |

## 2. 結論の要約

1. **H16（既知の手法の再発見）：「はい」。** 1 つの成分のモデルでは、すべてで次の 3 つが現れ、参照の実装と数値で一致した（差 1e-8 以下。実際は 1e-13 程度）。
   - メッセージが同時、λ = 0：IMM（予測の前に、前の時刻のモードについてまとめる）。
   - メッセージが同時、λ = 10⁶：GPB2（観測で更新した後にまとめる）。
   - メッセージを分ける：GPB1。
   - 外れ値のモデルでは、モードが時刻ごとに独立なので、IMM と GPB1 は同じ計算になり、1 つだけが出た。
2. **演算回数と誤差のつりあい。** 演算回数は GPB1 < IMM < GPB2、誤差はその逆。どのモデルでも同じ順だった。
3. **H17（構造の利用）：「はい」。** 独立な目標のモデルで、egfg は目標ごとに IMM・GPB2・GPB1 を行う計算を選んだ。結果は状態全体に適用した手法と数値で一致し（誤差は同じ）、演算回数は 1/6〜1/75 だった。
4. **H18（誤差の上界）：上界は正しいが、すぐに 1 に張りつく。** 1 次元の数値積分で求めた実際の TV を、毎回上回った。しかし 1〜4 ステップで 1（自明な値）に達する。観測による増幅の上界が緩いため。参考値として記録した「まとめの KL の上界の和」は、同じメッセージの形の中では、実際の誤差と同じ順に並んだ。

## 3. 1 つの成分のモデル

演算回数は 1 ステップあたり（モーメント形式）。誤差は種 3 つの平均。「モードの TV」は各時刻のモードの確率の TV の最大、「平均の誤差」は各時刻の平均の差を厳密な事後分布の標準偏差で割ったもの（マハラノビス距離）の最大。「1 次元の TV」は、メッセージの同時分布（モードと状態）の TV を数値積分で求めたものの最大。

| モデル | 手法（一致した参照） | 演算回数 | モードの TV | 平均の誤差 | 1 次元の TV | T=50 で GPB2 との差 |
|---|---|---|---|---|---|---|
| maneuver(2,1) | GPB1 | 18 | 0.095 | 0.17 | 0.34 | 0.49 |
| | IMM | 22 | 0.012 | 0.057 | 0.041 | 0.11 |
| | GPB2 | 32 | 0.0014 | 0.0038 | 0.016 | 0 |
| maneuver(3,1) | GPB1 | 30 | 0.18 | 0.22 | 0.33 | 0.41 |
| | IMM | 39 | 0.016 | 0.062 | 0.048 | 0.069 |
| | GPB2 | 69 | 0.0025 | 0.0066 | 0.013 | 0 |
| maneuver(2,2) | GPB1 | 62 | 0.22 | 0.31 | | 0.49 |
| | IMM | 82 | 0.058 | 0.13 | | 0.18 |
| | GPB2 | 128 | 0.026 | 0.055 | | 0 |
| maneuver(3,2,obs) | GPB1 | 96 | 0.44 | 0.84 | | 37 |
| | IMM | 141 | 0.066 | 0.19 | | 0.34 |
| | GPB2 | 279 | 0.0097 | 0.057 | | 0 |
| outlier(1) | IMM = GPB1 | 12 | 0.011 | 0.10 | 0.092 | 0.15 |
| outlier(2) | IMM = GPB1 | 76 | 0.0002 | 0.018 | | 0.062 |

- GPB1 は、モードで観測の雑音も変わるモデル（maneuver(3,2,obs)）では、長い実行で追跡を失った（GPB2 との差が標準偏差の 37 倍）。メッセージを 1 つのガウスにまとめると、モードと状態の関係が失われるため。
- IMM は、GPB2 のおよそ半分の演算回数で、GPB1 よりずっと小さい誤差。よく知られた評価と同じ。

## 4. 独立な目標のモデル（H17）

| モデル | 手法 | egfg（目標ごと）の演算回数 | 状態全体の演算回数 | 比 |
|---|---|---|---|---|
| targets(2,2,1) | IMM | 44 | 280 | 1/6.4 |
| | GPB2 | 76 | 760 | 1/10 |
| | GPB1 | 60 | 200 | 1/3.3 |
| targets(2,2,2) | IMM | 166 | 1136 | 1/6.8 |
| | GPB2 | 268 | 3344 | 1/12 |
| | GPB1 | 192 | 832 | 1/4.3 |
| targets(3,2,1) | GPB2 | 120 | 9000 | 1/75 |
| | GPB1 | 54〜64 | 1240 | 1/19〜1/23 |

- 誤差は、状態全体に適用した同じ手法と数値で一致した（モードの TV、平均の誤差、長い実行の差のすべて）。独立な目標なら、目標ごとに行っても状態全体で行っても同じ近似になる。状態全体では、モードの組の数（M^k）だけガウスを持つので高い。
- targets(3,2,1) では、目標ごとの IMM は出なかった。λ = 0 では、IMM より安い（69）が平均の誤差が大きい（0.23）計算が選ばれた。λ = 0 では近似の量を数えないので、まとめる位置が誤差の大きい側に寄る。
- 目標ごとにメッセージの形を混ぜたもの（一方の目標だけ分ける）は、どれも演算回数でも誤差でも、そろえたものより悪かった。

## 5. 誤差の上界（H18）

| 手法 | 上界 τ が 1 に達する時刻（平均） | まとめの KL の上界の和（最終時刻） |
|---|---|---|
| maneuver(2,1) の GPB1 / IMM / GPB2 | 2.0 / 2.7 / 4.3 | 0.88 / 0.20 / 0.052 |
| maneuver(3,2,obs) の GPB1 / IMM / GPB2 | 1.0 / 2.0 / 2.3 | 7.4 / 1.9 / 0.45 |

- **上界は正しい。** 1 次元のモデルで、すべての時刻とプログラムについて、上界は数値積分した TV を下回らなかった（テストでも確認）。
- **しかし、すぐに役に立たなくなる。** 観測による更新で、TV の上界は「尤度の最大値 ÷ 近似の分布での観測の予測確率」の 2 倍だけ増えうる。この倍率は 1 ステップで数倍になるので、上界は 1〜4 ステップで 1 に達する。1 回分の観測に対する最悪の場合を毎回仮定しているため。
- **参考値（まとめの KL の上界の和）は、同じメッセージの形の中では順位が正しい。** 1 つの成分のモデルでは、どれも GPB2 < IMM < GPB1 で、実際の誤差の順と一致した。ただし、これは厳密な上界ではない。メッセージの形が違うもの（目標ごとと状態全体）の間では、数え方が違うので比べられない。
- 前の議論のとおり、時間をまたいで使える保証には、観測についての仮定（観測がモデルから生まれる）のもとでの期待値の上界が要る（次の段階）。

## 6. 探索

- 1 つの成分のモデルは 0.2〜0.4 秒（すべてのメッセージの形と λ）。
- 2 つの目標は約 55 秒（メッセージの形 8 通り × λ 2 通り）。
- 3 つの目標では、幅優先の飽和はノード上限で早く打ち切られ、GPB2 も IMM も見つからなかった。段階分けの探索（staged）と全ての規則を使うと、目標ごとの GPB2 が見つかった（127 秒、メッセージの形をそろえた 2 通りだけ）。

## 7. 実装中に見つかった問題

- **メッセージの正規化。** 独立な成分に分けたメッセージは、他の成分の正規化の定数を毎ステップ取り込み、対数の重みが倍々に増えて、30 ステップほどで精度が落ちた。各ステップでメッセージを正規化して直した（テストは 40 ステップで確認）。
- **罰則の形。** 最初は「まとめる成分の数」だけに罰則をかけたが、IMM と GPB2 はまとめる成分の数が同じで、λ を変えても計算が変わらなかった。「まだ掛けていない観測の数」を掛けて、まとめる位置を区別できるようにした。観測を「まとめる値と変数を共有するものだけ」数える変形も試したが、IMM の位置（前の時刻の状態）と次の時刻の観測は変数を共有しないため、GPB2 が出なくなり、元に戻した。

## 8. 分かったこと

1. 近似を「e-graph の等式」ではなく「抽出が選ぶ実装」として入れると、e-graph の厳密さを保ったまま、既知の近似手法（GPB1、GPB2、IMM）を自動で再発見できる。手法の違いは、まとめる演算の置き場所とメッセージの形だけで表せた。
2. 構造があるモデル（独立な目標）では、既知の手法を状態全体に適用するより桁違いに安い計算を、同じ誤差で選ぶ。これは、離散やガウスの場合と同じく「構造を使った組み合わせ」の効果。
3. シミュレーションに頼らない実行時の上界は正しいが、観測による増幅の最悪の場合を毎回仮定するので、すぐ自明になる。実用的な誤差の保証には、観測についての仮定を入れた期待値の評価が必要。
4. 近似の量を事前に評価する仕組みがないので、λ による罰則は粗い目安。λ = 0 では、誤差の大きい置き場所が選ばれることがあった（3 つの目標）。
